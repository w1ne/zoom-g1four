# Prior art and findings — Zoom G1 Four (2026-09-27)

Consolidated research from web sources and live inspection of the connected unit.
Confidence tags: [V] verified by primary source or live test, [U] community
report not independently verified, [S] inference.

## Device (live-verified)

- Zoom G1 Four, firmware v2.00. USB `1686:04a1`, "ZOOM G Series",
  full-speed, AudioControl + MIDIStreaming interfaces. [V]
- Identity request `F0 7E 00 06 01 F7` -> `F0 7E 00 06 02 52 6E 00 0C 00 32 2E 30 30 F7`
  (model `0C 00` = G1 Four, version "2.00"). [V]
- Shared PID across G1 Four `0C 00`, G1X Four `0D 00`, B1 Four `0E 00`,
  B1X Four `0F 00`, GCE-3 `10 00`. Model is only knowable via SysEx identity. [V]
- `bcdDevice 0x0100` while shipped firmware is 2.00; the field is not the
  firmware version. [V]

## Hardware

- Board PCB-0993-02, shared by G1 Four / A1 Four / B1 Four; firmware images
  cross-flashable between models. DSP: **TMS320C6745DPTP3** (C674x, floating
  point, 176-pin HLQFP, USB 2.0 OTG full-speed). Flash: **MX25L3233F** 4 MB SPI
  NOR (A1 Four uses IS25LP032). Codec reported as "AC3101i", likely
  TLV320AIC3101 [S] on the audio path.
  Source: remont-aud.net dump thread; TI datasheets.
- Same DSP family as MS-50G / MS-70CDR (Zoom markets the DSP generation as
  "ZFX-IV"); old G1 (2009) is a different platform (NEC UPD78F0533 + ZFX-3). [V]
- No FCC internal photos found. No public JTAG/SWD pinout for PCB-0993-02. [V]
- G1X Four adds expression pedal hardware (CN1 header, SPI ADC IC4) not
  populated on G1 Four. Photos in mungewell/zoom-zt2 issue #18.

## Protocol

- All control is **USB-MIDI SysEx** over the class-compliant "ZOOM G Series"
  MIDI port — no vendor bulk protocol anywhere. [V]
- Reference implementation: `mungewell/zoom-zt2` (Python): file API (`60 xx`),
  patch up/download, `.ZD2` effect install, `FLST_SEQ.ZT2` handling, CRC32. [V]
- Checksum: `~CRC32` over the 7-bit-unpacked block
  (Barsik-Barbosik/Zoom-Firmware-Editor issue #16). [V]
- MS+ command table (same command language):
  `thammer/zoom-explorer`. `F0 52 00 6E 01 F7` = enter firmware mode. [V]
- Older MS-50G SysEx spec: `g200kg/zoom-ms-utility` (`midimessage.md`). [V]
- Effect/patch tooling ecosystem: `Barsik-Barbosik/Zoom-Firmware-Editor`,
  Zoom Effect Manager (zoomeffectmanager.com), `ELynx/zoom-fx-modding`,
  `repeat98/ZoomMultistompZDL`, `shooking/ZoomPedalFun`. [V]

## Firmware / updater format

- Official updater v2.00 (Mac zip / Win EXE) contains `ROM.bin` (163,840 B),
  `Main.bin` (493,412 B), `FS.bin` (3,137,536 B), `Preset.bin` (45,056 B),
  `MAIN_INFO.bin` (4,096 B). [V, agent inspection]
- Container: 32-byte file-table entries + 4096-byte content blocks with
  prev/next pointers; no signature/encryption observed; identity strings are
  plaintext (`G1 IV`, `G1X IV`, model bytes `6e 00 0d` in resource `133`). [V]
- Cross-model flashing works by editing updater resources; official updaters
  flash `ROM/Main/Preset` but do **not** restore the filesystem on G1 Four. [V]
- MS-70CDR precedent: updater bins combined into one 4 MB image and written to
  MX25L3233F with a CH341A after a brick. Offsets there:
  boot 0x000000, Main 0x040000, FS 0x0F0000. G1 Four offsets unverified. [V/U]

## Update mode / bootloader

- Enter update mode: hold both footswitches while plugging USB; screen shows
  FIRMWARE UPDATE; updater talks over USB-MIDI SysEx. Failed updates retryable. [V]
- MS+ generation flash opcodes were sniffed (issue #109): erase `0A`, write
  `02`, exit `04`, 5-byte 7-bit little-endian addresses, no read opcode found,
  MS+ flash map measured. G1 Four generation opcodes/behavior not fully
  documented. [V/U]
- One unverified report claims a full ~8 MB (2x duplicated 4 MB) read from a
  G1 Four in update mode. Treat as [U].

## Custom code precedent

- `.ZD2`/`.ZDL` effects are `ZDLF`-wrapped **TI C6000 ELF** objects for the
  C6745 (issue #93, #54, #87). [V]
- Custom DSP effects compiled with TI C6000 tools run on retail MS-70CDR
  (ZDL ABI, `repeat98/ZoomMultistompZDL`); ZD2 ABI only partially mapped. [V]
- Users have patched stock ZD2 modules (params/coefficients) and had them run;
  changing category IDs corrupted the filesystem (issue #109). [V]
- No public true custom firmware (OS replacement) exists for any Zoom pedal. [V]

## Brick / recovery notes

- FS writes can leave the pedal unbootable and immune to official re-flash
  (issues #37, #53). Community recovery: short the SPI EEPROM data pin to GND
  (~100 Ohm) during boot to force a filesystem rebuild; last resort is chip-off
  reflash with a dump. [V]
- Keep original updater zips pristine; back up patches + FS before any write.
