# P1 protocol notes: ZD2 USB-MIDI SysEx (2026-09-27)

Source: ported from mungewell/zoom-zt2 at commit
b1f63b0bee6d2d1bc9755958fc8cf15887efbdcf (MIT). See THIRD_PARTY_NOTICES.md.
All packets below are SysEx payloads (without F0/F7).

## Modes and identity

| Operation | Payload | Notes |
|---|---|---|
| PC mode on / off | `52 00 6e 52` / `52 00 6e 53` | required for patch/file operations |
| Identity request | `7E 00 06 01` | reply `7E 00 06 02 52 6e 00 <model lo> <model hi> <version ascii>` |

Live-verified on the target unit: model `0C 00` = G1 Four, firmware `2.00`.

## Patches

| Operation | Payload | Notes |
|---|---|---|
| Info | `52 00 6e 44` | count = `p[5]*128+p[4]`, patch size = `p[7]*128+p[6]`, bank size = `p[11]*128+p[10]` |
| Download | `52 00 6e 46 00 00 <bank&7f> <bank>>7> <loc&7f> <loc>>7>` | reply: length = `p[11]*128+p[10]`, data = `unpack(p[12:12+length+length//7+1])`, 5-byte inverted CRC32 in `p[-5:]` |

`bank = (location-1)//bsize`, `loc = location - bank*bsize - 1`, locations 1-based.

## Filesystem

| Operation | Payload | Notes |
|---|---|---|
| Check | `52 00 6e 60 25 00 00 <name> 00`, then `60 05 00`, then `60 27` | exists iff second reply ends in five zero bytes |
| List first/next | `52 00 6e 60 25/26 00 00 * 00` | reply[4]==4: name in reply[14:27] up to NUL; empty reply = end |
| Open read | `52 00 6e 60 20 02 00*9 <name> 00` | sent twice per the reference implementation; hardware-verified |
| Read block | `60 05 00`, `60 22 14 2f 60 00 0c 00 04 00 00 00`, `60 05 00` | last reply: len = `p[9]*128+p[8]`; stop on `p[4]!=4` or len 0 |
| Close | `60 21 40 00 00 00 00`, then `60 09` | |

Follow-up packets after the open request omit the `52 00 6e` prefix, matching
the reference implementation (`60 xx` follow-ups).

## Framing

- 7-bit packing: groups of 7 data bytes become 1 MSB byte + 7 payload bytes.
- CRC: `binascii.crc32(data) ^ 0xFFFFFFFF` transmitted as 5 little-endian
  7-bit groups (4×7 bits + 4 bits).
- The same framing is used for patch and file transfers.
